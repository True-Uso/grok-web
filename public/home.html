同一种需求，三种做法

在输入框旁边就能切换。它们是工作方式，不是三个产品。

单 Agent

一个人做完。适合一个页面、小改动、想马上看到。

  • 一个 Agent 从头做到完

多 Agent

主 Agent 分工，调研、实现、验收分开看进度。

  • 调研子 Agent · 读代码、搜资料
  • 实现子 Agent · 改文件、写功能
  • 验收子 Agent · 跑命令、核对结果

工厂模式

界面、系统、验收三条线一起推进，点进一层能看到正在做什么。

  • 一层 · 产线甲 · 界面
  • 二层 · 产线乙 · 系统
  • 三层 · 产线丙 · 验收

工厂模式是三层工作室，不是流水线幻灯片

一层做界面，二层做系统和数据，三层做检查收口。这是同一个项目里的分工，不是同时开三个无关项目。

「厂长指令：三条线并行。点进某一层，看他们正在做什么。」

一层产线甲 · 界面
页面样式交互
二层产线乙 · 系统
接口数据容器
三层产线丙 · 验收
运行检查收口

同一个会话，三层分工。

做完以后，你能带走这些

预览

右边直接打开页面；要存数据的系统，会在容器里跑起来再预览。

下载

把源码打成压缩包带走。

发布

生成一个别人打得开的链接。

存档

把能用的一版存下来，以后还能回去。

小页面，或能存数据的系统

小页面

一个 HTML，做完就能玩、能看。小游戏、展示页、不存数据的小工具，都属于这一种。

index.html

能存数据的系统

做成真正能跑的应用（现在是 Node.js + SQLite）。登记、进销存、登录、后台这类要存数据或多人用的系统走这条路。

Dockerfile:8080

这一种的预览需要本机 Docker 可用。没开 Docker 时，先看代码、先下载都行。
